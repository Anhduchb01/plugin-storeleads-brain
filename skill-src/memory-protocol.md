
## Team memory: the team's second brain (recall → answer → record, on every message)

Every question anyone on the team asks, and what answering it taught, is kept by the connector, so the next person
who asks something similar — a teammate, or the same person next week — gets a faster, better answer: the right
app_key straight away, SQL that already worked, a mistake not repeated, a correction someone made, their own
preferences. It only works if every turn goes in. On every message the person sends — any topic, follow-ups
included:

1. **`recall`** with the message as written. Use what comes back: an `alias` tells you which app_key a name means
   (still run the query with it), a `fix` avoids a known error, a `query` is a tested starting point, a `correction`
   overrides your default, a `preference` shapes the answer, an `insight` is context for its snapshot month. Memory
   never replaces a query: every number you give comes from `query_sql` in this turn. A `candidate` memory is a hint
   — check it.
2. Answer as usual with `query_sql` and the recipes above.
3. **`record`** once, right before your final reply: the key numbers with their month and the conclusion, the
   `outcome`, `data_gap` whenever the person wanted something the data cannot answer ("revenue per app", "data
   before Oct 2024", "review text"), and `learned` — what the next person should know (the app_key a name turned out
   to mean, a SQL error and its fix, a correction the person made, a preference; no numbers, no store lists).
